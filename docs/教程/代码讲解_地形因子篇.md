# 代码讲解 · 地形因子篇（M2 + M3）

这一篇对应 `pipeline/process/` 下的四个脚本，以及它们产出的五个中间文件。

```
terrain.py      DEM 读入 → 坐标校验 → 修负高程 → 存 .npy
fill_sinks.py   填洼（Priority-Flood + ε）     -> wuhan_dem_filled.npy / wuhan_dem_filldepth.npy
slope.py        坡度（Horn 3×3）                -> wuhan_slope.npy
flow.py         汇流（D8 + 拓扑累加）            -> wuhan_flowacc.npy
flood_index.py  归一化 → 加权合成 → 分级        -> wuhan_flood_index.npy
```

跑的顺序不能变：填洼要用高程，坡度要用**填洼后**的高程，汇流要用**填洼且带微坡度**的高程，
指数要用全部四个。这是一条严格的数据依赖链。

---

## 一、填洼：为什么这一步绕不过去

DEM 是雷达测出来的，每个像元是一个"坑"：下雨后水往低处流，如果某个像元四周都比它高，
水就永久停在那里。这样的像元叫 **sink**（洼地/汇）。

不填洼直接算汇流，会得到一堆互不相连的小水塘，长江会断成几万节。

但**填洼会改变地形**，所以必须回答一个问题：**凭什么把它填到那个高度？**

答案是"水能漫出去的最低高度"，也就是这个洼地的 **溢出口**（spill point）。
Priority-Flood 算法就是模拟"水从边界往内陆漫"的过程，漫到溢出口就停，正好得到这个高度。

### 算法的三个关键点

**1. 为什么用小顶堆，而不是排序后遍历？**

因为水是**先淹最低处**的。小顶堆每次弹出当前水位最低的像元，保证"水位从低到高"的顺序，
和真实淹没过程一致。用排序做不到，因为一个像元的水位取决于它的邻居，是动态变化的。

**2. 为什么"第一次弹出即定稿"？**

这和 Dijkstra 最短路是同一个思想：**当前水位最低的那个像元，不可能再被更低的水淹到**。
所以弹出时直接标记 `closed`，后面不再修改。这一条是整个算法正确性的核心。

**3. ε 是干什么的**

填完之后，一大片被淹的像元高程**完全相等**。D8 算流向时要找"最陡的下坡"，
八个邻居一样高，就没有下坡，于是每个像元都成了独立的水槽——**长江又断了**。

解法是填的时候让被淹的像元比水位高 0.1 毫米：

```python
if new_z <= z:
    new_z = z + 1e-4
```

0.1 毫米对高程、坡度、填深的影响都可以忽略，但足以让 D8 分出上下游。

> **可迁移的经验**：当两个值在数学上相等、而算法需要它们有先后时，
> 加一个远小于业务精度的扰动来打破平局。排序不稳定、哈希冲突、浮点比较都用得上这招。

## 二、坡度：公式简单，坑在数据

Horn 公式（3×3 窗口，权重 1:2:1）：

```
dzdx = [(z3 + 2·z6 + z9) - (z1 + 2·z4 + z7)] / (8 · res)
dzdy = [(z7 + 2·z8 + z9) - (z1 + 2·z2 + z3)] / (8 · res)
slope = arctan(sqrt(dzdx² + dzdy²)) · 180 / π
```

`res` 是像元边长（本项目 30 米）。分母必须写成 `(8 * res)`，写成 `/ 8 * res`
就变成"先除以 8 再乘 30"，结果差 900 倍，而坡度图看起来还挺像回事。

### 为什么图上有一条"不属于长江"的白带

第一版坡度图里，长江位置是一条高坡度带，很反直觉——水面应该是最平的。

按高程分层统计后才看清楚：

| 高程带 | 坡度中位数 | <1° 占比 |
|---|---|---|
| <22 m（江面/滩地） | **0.000°** | 92.4% |
| 22~40 m（城区） | 0.658° | 56.4% |
| 40~100 m | 3.308° | 14.4% |
| >100 m（山地） | 16.254° | 1.8% |

江面本身确实是 0°，那条白带是**两岸堤防**：比江面高 5~8 米，在 30 米格网上就是一道陡坎。

> **方法**：全图平均会骗人。异常现象要**分层**看，按高程、按区域、按坡度分档，
> 真相往往在某一层里。

### DSM 的第三次"作案"

Copernicus 是 DSM（地表模型，含建筑和树冠），不是 DTM（裸地面）。所以：

- 首次：湖里记录的是水下地形，出现 −152 米的负高程
- 其次：两栋楼之间形成大量"假碗"，填洼时 30% 的像元被填
- 再次：江汉路算出 6.83° 坡度，其实是楼顶到街道的落差

城市内涝要用 DTM，或者至少用建筑掩膜把楼顶剔掉。这是本项目已知的系统偏差。

## 三、汇流：难在顺序，不难在公式

D8 的意思是：每个像元往**八个邻居里最陡的那个**流。流向确定后，累积量就是
"有多少个像元的水最终经过我这里"。

```
acc[i] = 1 + Σ acc[所有流向 i 的上游像元]
```

这个式子看起来能直接循环算，但**顺序错了结果就全错**：
如果按行从上往下遍历，算到某个像元时，它的上游可能还没算完，只加到一个半成品。

正确做法是**按高程从高到低**处理：高处的像元一定不会被低处影响，所以轮到它时，
它的累积量已经是最终值。这就是"拓扑顺序"。

实现上用 `np.argsort` 拿到高程降序的索引，然后一维遍历：

```python
for idx in order:
    nr, nc = divmod(idx, w)
    flat_acc[nr * w + nc] += flat_acc[idx]
```

### 结果说明了什么

最大累积量 **2144 万**，全图有效像元 2268 万——**94.6% 的水最后汇到同一个出口**，
就是长江流出武汉市域的地方。

这是对整条链路最硬的验证：填洼、坡度、D8 任何一环错了，水不可能这么干净地汇到一个点。

## 四、归一化：不是套公式，是选尺子

四个因子量纲完全不同：

| 因子 | 范围 | 分布形状 |
|---|---|---|
| 高程 | 18 ~ 864 m | 右偏 |
| 坡度 | 0 ~ 62° | 右偏，46% 挤在 0 附近 |
| 填深 | 0 ~ 119 m | 一半是 0 |
| 汇流 | 1 ~ 2144 万 | **极端长尾**，p98 只有 1351 |

汇流最大值是 p98 的 1.6 万倍。如果按 `(x-min)/(max-min)` 归一化，
98% 的像元都会落在 0.0001 附近，图上一片死白。

所以用**分位数截断**：

```
u = clip((x - p_lo) / (p_hi - p_lo), 0, 1)
```

比 p_lo 低的一律 0，比 p_hi 高的一律 1。每个因子的截断区间单独定，理由写在
`flood_index.py` 顶部的 `CLIP` 表里。

### 方向不能忘

归一化只回答"这个值在这群数里算大还是小"，**不回答"大是不是坏事"**。

- 高程、坡度：越小越危险 → 用 `1 - u`
- 填深、汇流：越大越危险 → 保持 `u`

用 `1-u` 而不是 `-u`，是因为 `1-u` 仍在 [0,1]，量纲不变；`-u` 会变成负数，
加权求和时正负相消，结果没法解释。

## 五、权重：M3 唯一没有标准答案的地方

`WEIGHTS` 四个数相加必须等于 1。这组数字不是算出来的，是**选出来的**，背后是一句主张：

- 认为"地形低"最重要 → 调高高程权重
- 认为"水从哪来"最重要 → 调高汇流权重
- 拿不出理由 → 平权 0.25，但要在报告里承认这是"无信息先验"

真实的项目里，权重要么来自专家打分（AHP/德尔菲），要么来自**实测渍水点回归**。
我们现在没有标定数据，所以只能给出"相对风险排序"，不能声称"这里一定会淹"。

> 检验权重是否合理，最好的方法是**敏感性分析**：把某个权重 ±0.1，看高风险的
> 前 3% 像元挪动了多少。挪动很小说明结论稳健；挪动很大说明这套权重决定了结论，
> 那就必须给出更强的理由。

### 5.1 实测：三套权重差多少

`pipeline/analysis/sensitivity.py` 固定因子、只换权重，在剔除水体后的 7,077 km² 陆地上跑：

| 方案 | 高程 | 坡度 | 填深 | 汇流 | 均值 | 中位 |
|---|---|---|---|---|---|---|
| C 汇流主导（当前） | 0.20 | 0.15 | 0.15 | 0.50 | 0.327 | 0.305 |
| B 地形主导 | 0.30 | 0.25 | 0.15 | 0.30 | 0.421 | 0.435 |
| A 平权 | 0.25 | 0.25 | 0.25 | 0.25 | 0.387 | 0.395 |

| 对比 | Spearman 秩相关 | 前 3% 重合 | Jaccard |
|---|---|---|---|
| C vs B | 0.9720 | 82.4% | 0.701 |
| C vs A | 0.9687 | **68.3%** | 0.519 |
| B vs A | 0.9985 | 82.9% | 0.708 |

三句话读懂：

1. **秩相关 0.969~0.999**——整体排序几乎不受权重影响，说明"哪里更危险"主要由地形
   决定，这是结论能成立的基础。
2. **前 3%：跟 B 重合 82%，跟 A 只能重合 68%**——大排序稳，但"极高"这一档还有
   1/5~1/3 会换人。所以只能说"相对风险排序"，不能说"这 212 km² 一定会淹"。
3. **C 和 A 差得最远（68%）**——合理：A 把 0.25 给了填深，而填深有一半像元是 0，
   剩下的一半里混着大量 DSM 建筑造成的假碗。一个"一半是零、另一半是噪声"的因子
   拿到高权重，顶档就会换掉三成。

> 这一格本来写的是 **51.2%**，是水体判据还是老版本时的结果。查下去发现：
> 被 C 判成"极高"的 217 km² 里，有 **51% 按新判据其实是湖面或江面**——
> 三套权重各自在不同湖面上"高度重视"，重合率当然难看。
> 水剔干净后分歧回到 68.3%，剩下的三成才真是权重差异。
> **指标异常时先查数据质量，别急着解释模型。**

> 这就是为什么"平权"不等于"中立"。**给一个质量差的因子平权，等于放大它的噪声。**

## 六、两个"不修就说不通"的坑

### 1. 水体必须剔除

任何地形汇水算法都会把湖心、江心排在最前面——它们本来就是水的终点。
实测：指数 ≥ 0.83 的像元里 **77% 是水面**。

把它们算进"极高易涝区"，等于用"湖里最湿"去证明"湖边最危险"，是循环论证。

**第一版按绝对高程划线，失败了。** 判据是「高程 ≤ 22 m 且坡度 < 0.1°」，
只对长江漫滩有效：东湖 26.4 m、南湖 26.9 m、沙湖 26.4 m，全都比 22 高一点点，
整片湖被当成高风险陆地；而真正该关注的沿江低地反倒被一刀切掉。

**第二版改用相对地形**（详见 8.2）：湖是封闭盆，水要翻过出水口才流得走，所以要"填"；
沿江平地本来就是斜的，填深是 0。实测湖心填深 3.8~12.4 m，低洼陆地全是 0.00 m。

### 2. 必须裁到市域

DEM 是 1°×1° 分幅拼出来的**矩形**，天然包含孝感、黄冈、鄂州的一部分。
不裁的话，"陆地面积"会算成 17,751 km²，是市域面积的两倍，所有占比都是假的。

裁剪后：**8,573 km²，官方 8,569，差 0.0%**。这个校验和"区县面积合计 = 市级面积"
是同一个思路：**用另一个独立来源的数字卡住自己**。

## 七、分级：为什么不用固定阈值

第一版用 0.65 当"极高"的界限，算出 **5,119 km²**，占全市 60%。
一张把六成城区标成"极高"的图，等于什么都没说。

改成按陆地指数的分位数切：

| 等级 | 分位 | 面积 |
|---|---|---|
| 低 | 后 35% | 2,477 km² |
| 较低 | 35~65% | 2,123 km² |
| 中 | 65~88% | 1,628 km² |
| 高 | 88~97% | 637 km² |
| 极高 | 前 3% | **212 km²** |

（陆地合计 7,077 km²，水体 1,496 km²。旧判据下是 7,246 和 1,327——水体面积只多了 169 km²，
但**成分完全换了**：旧的是沿江低地，新的是湖面与江面。详见 8.2。）

代价是：换一套权重，边界会跟着动，两版结果不能逐像素比较。
要发论文就得用实测渍水点标定绝对阈值——我们没有，所以只声明"相对风险"。

### 8.1 上球之后的回查（实测证据）

贴图叠到卫星影像上以后，又做了两处体检，结论比空口说"已知局限"有力：

**① 山区的红色不是误报。** 黄陂南部那几条像"火苗"的红条，读数如下：

| 点位 | 高程 | 坡度 | 汇流 | 指数 |
|---|---|---|---|---|
| 红条最亮处 | 23.7 m | **0.00°** | 18,852 | 0.927 |
| 同上（另一处） | 21.4 m | **0.00°** | 1,475,874 | 0.920 |
| 木兰山 | 225.3 m | 2.92° | 16 | 0.264（较低） |

红条是**滠水河谷的平坦河床**，两侧山坡才是山。山坡的坡度上去了，指数自然下来。
"看着像山上着火"，是因为河谷在山区里是一条窄带，形状像火苗。

**② 水体判据确实漏了大湖。** 汤逊湖水面高程 **26.9 m**，高于 22 m 的门槛，
没被剔掉，被判成"极高"（0.729）。南湖、沙湖这类 24~30 m 的湖会同样中招。

> **用绝对高程做水体判据，只对长江漫滩有效。** 武汉的湖面高程从 19 m 到 27 m 不等，
> 一条水平线切不干净。这也解释了为什么"剔除水体"那条规则看起来生效了，
> 却仍有个别湖泊拿到满分——生效的部分是江，没生效的是湖。

这条已于 2026-11-24 修掉，过程见下节。

### 8.2 水体判据改造：从「绝对高程」到「相对地形」

**问题**：8.1 的 ② 查出来，东湖 26.4 m、南湖 26.9 m、沙湖 26.4 m，全都躲过了 22 m 的线。

**思路**：不引外部水体数据，改用 DEM 自己的形状信息。关键变量是**填洼深度**——

- 湖是个封闭盆：水要翻过四周的岸才能流走，Priority-Flood 会把它填到出水口高度
- 沿江平地是斜的：水自己会走，填深接近 0
- 建筑围成的假碗：填深也有，但面积小、连不成片

实测（11×11 邻域中位数，约 330 m 见方）：

| 点位 | 高程 m | 填深 m | 坡度 ° |
|---|---|---|---|
| 东湖·湖心 | 26.4 | **4.79** | 0.000 |
| 南湖·湖心 | 26.9 | **4.14** | 0.000 |
| 沙湖·湖心 | 26.4 | **3.82** | 0.000 |
| 汤逊湖·湖心 | 26.9 | **12.37** | 0.000 |
| 长江·江心 | 21.3 | **6.34** | 0.000 |
| 汉口江滩 | 29.3 | 0.00 | 1.401 |
| 武昌站 | 27.3 | 0.00 | 1.778 |
| 四新（低地） | 26.4 | 0.00 | 1.373 |
| 青山建一 | 26.9 | 0.00 | 1.794 |

水陆在填深上差了一个数量级，比高程那条线干净得多。

**三个条件 + 一道面积门槛**：

```python
candidate = (slope < 0.1) & (fill > 3.0) & (elev < 35.0)
# 再按 8 邻域做连通域标记，剔掉面积 < 0.3 km² 的零碎小坑
```

- `slope < 0.1`：水面是绝对平的，实测全 0.000°
- `fill > 3.0`：不能卡太高——东湖湖心只有 4.79 m，卡到 5 就把东湖漏了
- `elev < 35`：挡山区假湖。全域满足前两条的有 3,171 km²，拆成连通域看，
  前 14 名都是湖（梁子湖 890、牛山湖 340、涨渡湖 280…），第 15 名却是黄陂山区
  一个 29 km²、高程 61.6 m 的洼地，不是水
- `面积 > 0.3 km²`：挡院子、楼间空地这种围合小坑

**结果**：水体 1,496 km²（占市域 17.5%）。验收用 11 个点位，全过：

| 类型 | 点位 | 判定 |
|---|---|---|
| 水 | 东湖 / 南湖 / 沙湖 / 汤逊湖湖心、长江江心 | 5/5 判为水体 |
| 陆 | 南湖雅园、汤逊湖文化大道、后湖、四新、青山建一、武昌站 | 6/6 有等级 |

渍水点等级：汤逊湖·文化大道 高、武昌站 中、南湖·雅园 较低、青山建一 较低、四新 低。
地形解释不了"客水顶托"和泵站问题，这组结果和现实是吻合的。

**踩到的两个坑，比结论更值钱**：

1. **验收脚本读错了文件。** `wuhan_flood_index.npy` 存的是完整指数，水体位置也有数值
   （只是统计和出图时被 mask 掉）；真正把水体写成 NaN 的是导出的 `.bin`。
   拿 `.npy` 判水，会得出"湖心是陆地"的错误结论，然后去改一个本来正确的算法。
2. **验收点选在了水里。** 最初写的「南湖（洪山）114.335,30.485」「后湖（江岸）
   114.305,30.650」，查填深才发现它们本身就在湖面上（fill 1.9~3.6 m、坡度 0）。
   那不是判据误伤陆地，是坐标取错了。**验收点选错，会把正确的算法判成 bug。**

**代价**：面积 < 0.3 km² 的小池塘不剔。武汉坑塘约 1,100 km²，大多是鱼塘，
单个面积小、对城市内涝影响也小，留着不改变分级结论。要精确还是得上 WorldCover 10 m。

这个漏网不是猜的。图上点过一个典型位置（114.0051, 30.7268，东西湖柏泉一带）：

| 指标 | 读数 | 说明 |
|---|---|---|
| 高程 | 22.5 m | 21×21 邻域（约 630 m 见方）**全是 22.5 m**，一个整数 |
| 坡度 | 0.000° | 明显是人工推平的塘埂或鱼塘 |
| 填深 | 2.26 m | 就卡在 3 m 门槛下面，连通域面积也不到 0.3 km² |
| 指数 | 0.625 | 判为「高」 |

也就是说：**浅塘躲得过填深门槛，因为它四周的塘埂只比水面高一米多**。这类地方雨天确实积水，
但那是鱼塘不是街道，指标偏保守而非偏乐观，暂时接受。
