# 代码讲解 · 地形因子篇（M2 + M3）

这一篇对应 `pipeline/process/` 下的四个脚本，以及它们产出的五个中间文件。

```
terrain.py      DEM 读入 → 坐标校验 → 修负高程 → 存 .npy
fill_sinks.py   填洼（Priority-Flood + ε）     -> wuhan_dem_filled.npy / wuhan_dem_filldepth.npy
slope.py        坡度（Horn 3×3）                -> wuhan_slope.npy
flow.py         汇流（D8 + 拓扑累加）            -> wuhan_flowacc.npy
flood_index.py  归一化 → 加权合成 → 分级        -> wuhan_flood_index.npy
```

跑的顺序不能变：填洼要用高程，坡度要用**填洼后**的高程，汇流要用**填洼且带微坡度**的高程，
指数要用全部四个。这是一条严格的数据依赖链。

---

## 一、填洼：为什么这一步绕不过去

DEM 是雷达测出来的，每个像元是一个"坑"：下雨后水往低处流，如果某个像元四周都比它高，
水就永久停在那里。这样的像元叫 **sink**（洼地/汇）。

不填洼直接算汇流，会得到一堆互不相连的小水塘，长江会断成几万节。

但**填洼会改变地形**，所以必须回答一个问题：**凭什么把它填到那个高度？**

答案是"水能漫出去的最低高度"，也就是这个洼地的 **溢出口**（spill point）。
Priority-Flood 算法就是模拟"水从边界往内陆漫"的过程，漫到溢出口就停，正好得到这个高度。

### 算法的三个关键点

**1. 为什么用小顶堆，而不是排序后遍历？**

因为水是**先淹最低处**的。小顶堆每次弹出当前水位最低的像元，保证"水位从低到高"的顺序，
和真实淹没过程一致。用排序做不到，因为一个像元的水位取决于它的邻居，是动态变化的。

**2. 为什么"第一次弹出即定稿"？**

这和 Dijkstra 最短路是同一个思想：**当前水位最低的那个像元，不可能再被更低的水淹到**。
所以弹出时直接标记 `closed`，后面不再修改。这一条是整个算法正确性的核心。

**3. ε 是干什么的**

填完之后，一大片被淹的像元高程**完全相等**。D8 算流向时要找"最陡的下坡"，
八个邻居一样高，就没有下坡，于是每个像元都成了独立的水槽——**长江又断了**。

解法是填的时候让被淹的像元比水位高 0.1 毫米：

```python
if new_z <= z:
    new_z = z + 1e-4
```

0.1 毫米对高程、坡度、填深的影响都可以忽略，但足以让 D8 分出上下游。

> **可迁移的经验**：当两个值在数学上相等、而算法需要它们有先后时，
> 加一个远小于业务精度的扰动来打破平局。排序不稳定、哈希冲突、浮点比较都用得上这招。

## 二、坡度：公式简单，坑在数据

Horn 公式（3×3 窗口，权重 1:2:1）：

```
dzdx = [(z3 + 2·z6 + z9) - (z1 + 2·z4 + z7)] / (8 · res)
dzdy = [(z7 + 2·z8 + z9) - (z1 + 2·z2 + z3)] / (8 · res)
slope = arctan(sqrt(dzdx² + dzdy²)) · 180 / π
```

`res` 是像元边长（本项目 30 米）。分母必须写成 `(8 * res)`，写成 `/ 8 * res`
就变成"先除以 8 再乘 30"，结果差 900 倍，而坡度图看起来还挺像回事。

### 为什么图上有一条"不属于长江"的白带

第一版坡度图里，长江位置是一条高坡度带，很反直觉——水面应该是最平的。

按高程分层统计后才看清楚：

| 高程带 | 坡度中位数 | <1° 占比 |
|---|---|---|
| <22 m（江面/滩地） | **0.000°** | 92.4% |
| 22~40 m（城区） | 0.658° | 56.4% |
| 40~100 m | 3.308° | 14.4% |
| >100 m（山地） | 16.254° | 1.8% |

江面本身确实是 0°，那条白带是**两岸堤防**：比江面高 5~8 米，在 30 米格网上就是一道陡坎。

> **方法**：全图平均会骗人。异常现象要**分层**看，按高程、按区域、按坡度分档，
> 真相往往在某一层里。

### DSM 的第三次"作案"

Copernicus 是 DSM（地表模型，含建筑和树冠），不是 DTM（裸地面）。所以：

- 首次：湖里记录的是水下地形，出现 −152 米的负高程
- 其次：两栋楼之间形成大量"假碗"，填洼时 30% 的像元被填
- 再次：江汉路算出 6.83° 坡度，其实是楼顶到街道的落差

城市内涝要用 DTM，或者至少用建筑掩膜把楼顶剔掉。这是本项目已知的系统偏差。

## 三、汇流：难在顺序，不难在公式

D8 的意思是：每个像元往**八个邻居里最陡的那个**流。流向确定后，累积量就是
"有多少个像元的水最终经过我这里"。

```
acc[i] = 1 + Σ acc[所有流向 i 的上游像元]
```

这个式子看起来能直接循环算，但**顺序错了结果就全错**：
如果按行从上往下遍历，算到某个像元时，它的上游可能还没算完，只加到一个半成品。

正确做法是**按高程从高到低**处理：高处的像元一定不会被低处影响，所以轮到它时，
它的累积量已经是最终值。这就是"拓扑顺序"。

实现上用 `np.argsort` 拿到高程降序的索引，然后一维遍历：

```python
for idx in order:
    nr, nc = divmod(idx, w)
    flat_acc[nr * w + nc] += flat_acc[idx]
```

### 结果说明了什么

最大累积量 **2144 万**，全图有效像元 2268 万——**94.6% 的水最后汇到同一个出口**，
就是长江流出武汉市域的地方。

这是对整条链路最硬的验证：填洼、坡度、D8 任何一环错了，水不可能这么干净地汇到一个点。

## 四、归一化：不是套公式，是选尺子

四个因子量纲完全不同：

| 因子 | 范围 | 分布形状 |
|---|---|---|
| 高程 | 18 ~ 864 m | 右偏 |
| 坡度 | 0 ~ 62° | 右偏，46% 挤在 0 附近 |
| 填深 | 0 ~ 119 m | 一半是 0 |
| 汇流 | 1 ~ 2144 万 | **极端长尾**，p98 只有 1351 |

汇流最大值是 p98 的 1.6 万倍。如果按 `(x-min)/(max-min)` 归一化，
98% 的像元都会落在 0.0001 附近，图上一片死白。

所以用**分位数截断**：

```
u = clip((x - p_lo) / (p_hi - p_lo), 0, 1)
```

比 p_lo 低的一律 0，比 p_hi 高的一律 1。每个因子的截断区间单独定，理由写在
`flood_index.py` 顶部的 `CLIP` 表里。

### 方向不能忘

归一化只回答"这个值在这群数里算大还是小"，**不回答"大是不是坏事"**。

- 高程、坡度：越小越危险 → 用 `1 - u`
- 填深、汇流：越大越危险 → 保持 `u`

用 `1-u` 而不是 `-u`，是因为 `1-u` 仍在 [0,1]，量纲不变；`-u` 会变成负数，
加权求和时正负相消，结果没法解释。

## 五、权重：M3 唯一没有标准答案的地方

`WEIGHTS` 四个数相加必须等于 1。这组数字不是算出来的，是**选出来的**，背后是一句主张：

- 认为"地形低"最重要 → 调高高程权重
- 认为"水从哪来"最重要 → 调高汇流权重
- 拿不出理由 → 平权 0.25，但要在报告里承认这是"无信息先验"

真实的项目里，权重要么来自专家打分（AHP/德尔菲），要么来自**实测渍水点回归**。
我们现在没有标定数据，所以只能给出"相对风险排序"，不能声称"这里一定会淹"。

> 检验权重是否合理，最好的方法是**敏感性分析**：把某个权重 ±0.1，看高风险的
> 前 3% 像元挪动了多少。挪动很小说明结论稳健；挪动很大说明这套权重决定了结论，
> 那就必须给出更强的理由。

## 六、两个"不修就说不通"的坑

### 1. 水体必须剔除

任何地形汇水算法都会把湖心、江心排在最前面——它们本来就是水的终点。
实测：指数 ≥ 0.83 的像元里 **77% 是水面**。

把它们算进"极高易涝区"，等于用"湖里最湿"去证明"湖边最危险"，是循环论证。

当前用的是粗糙判据（高程 ≤ 22 m 且坡度 < 0.1°），代价是把沿江最低那一层平地
（真实的易涝区）也一起划掉。下一步换 ESA WorldCover 或 OSM 水系。

### 2. 必须裁到市域

DEM 是 1°×1° 分幅拼出来的**矩形**，天然包含孝感、黄冈、鄂州的一部分。
不裁的话，"陆地面积"会算成 17,751 km²，是市域面积的两倍，所有占比都是假的。

裁剪后：**8,573 km²，官方 8,569，差 0.0%**。这个校验和"区县面积合计 = 市级面积"
是同一个思路：**用另一个独立来源的数字卡住自己**。

## 七、分级：为什么不用固定阈值

第一版用 0.65 当"极高"的界限，算出 **5,119 km²**，占全市 60%。
一张把六成城区标成"极高"的图，等于什么都没说。

改成按陆地指数的分位数切：

| 等级 | 分位 | 面积 |
|---|---|---|
| 低 | 后 35% | 2,536 km² |
| 较低 | 35~65% | 2,174 km² |
| 中 | 65~88% | 1,667 km² |
| 高 | 88~97% | 652 km² |
| 极高 | 前 3% | **217 km²** |

代价是：换一套权重，边界会跟着动，两版结果不能逐像素比较。
要发论文就得用实测渍水点标定绝对阈值——我们没有，所以只声明"相对风险"。
