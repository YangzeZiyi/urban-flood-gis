二、七大模块拆解

每个模块都写清三件事：做什么、产出什么、怎么算做完。按这个顺序做，做完一个就提交一次 Git，不要憋大招。

M1 · 数据采集模块

Python第 3 周约 10 小时

做什么：

  • 用 requests + BeautifulSoup 抓取目标城市的降雨数据（气象站日/小时降雨量），或用公开 API（如和风天气免费额度）。
  • 下载 SRTM 30m DEM 数字高程数据（公开免费，覆盖全国）。
  • 下载 OSM 路网、水系、行政区边界（Geofabrik 提供按省打包）。
  • 统一坐标系：全部转成 EPSG:4326（经纬度）入库，前端展示时再转。

产出：data/raw/ 原始数据 + data/clean/ 清洗后的 CSV / GeoJSON。

怎么算做完：写一个 fetch.py，一条命令跑完，输出干净数据；断电重跑结果一致。

M2 · 空间数据处理与建模

Python第 4 周约 14 小时

做什么：

  • DEM 填洼（填平内部凹陷）、计算坡度、汇流累积量——这是判断"哪里容易积水"的基础。
  • 提取低洼易涝区：高程低于周边、坡度小、汇流量大的区域。
  • 把结果做成矢量面（易涝区多边形）和栅格（风险等级图）两套。
  • 写进 PostGIS。

产出：易涝区矢量图层（.shp / GeoJSON）+ 风险栅格（GeoTIFF）+ 入库脚本。

怎么算做完：在 QGIS 或 pgAdmin 里能看到图，且和真实易涝点位置大致对得上（拿新闻里的积水点验证 2-3 个）。

这一步最容易卡住。如果 3 天做不出来，就砍掉"汇流累积"，只用"高程 + 坡度"做简化版易涝区判定。作品不需要学术严谨，需要能跑通、能讲清逻辑。

M3 · 空间数据库设计

PostGIS第 4 周约 4 小时

做什么：建三张核心表，全部加空间索引（GiST）：

-- 易涝风险区
CREATE TABLE flood_zone (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100),
  risk_level SMALLINT,          -- 1低 2中 3高 4极高
  area_m2  NUMERIC,
  geom GEOMETRY(Polygon, 4326)
);
CREATE INDEX idx_flood_geom ON flood_zone USING GIST(geom);

-- 降雨站点
CREATE TABLE rain_station (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100),
  geom GEOMETRY(Point, 4326)
);

-- 降雨记录
CREATE TABLE rain_record (
  id SERIAL PRIMARY KEY,
  station_id INT REFERENCES rain_station(id),
  obs_time TIMESTAMP,
  rainfall_mm NUMERIC
);
CREATE INDEX idx_rain_time ON rain_record(obs_time);

产出：schema.sql 建表脚本 + 初始化数据。

怎么算做完：能执行 SELECT ST_AsGeoJSON(geom) FROM flood_zone; 拿到标准 GeoJSON。

M4 · 后端服务（Spring Boot）

Spring Boot第 5 周约 16 小时

做什么：提供 4 个 REST 接口：

接口说明
GET /api/zones返回全部易涝区 GeoJSON（供前端渲染）
GET /api/zones/{id}单个易涝区详情（面积、等级、历史积水次数）
GET /api/rain?start=&end=按时间范围查降雨序列
GET /api/risk?time=给定时刻的风险等级分布（调 M5 模型）

关键技术点：用 MyBatis 直接执行 SQL，几何字段用 ST_AsGeoJSON() 转字符串返回——不要用 hibernate-spatial，配置复杂、坑多，初学者容易被劝退。

产出：可运行的后端服务，端口 8080。

怎么算做完：Postman 调 4 个接口都返回 200 且数据结构正确。

M5 · 风险预测模型

算法第 6 周约 10 小时

做什么：两层，先简后繁：

  1. 风险评分（必做）：风险 = 降雨强度 × 权重 + 地形低洼度 × 权重 + 排水能力倒数 × 权重。权重先拍脑袋给，能出分级结果就行。
  2. 马尔科夫链预测（复用毕设）：把你毕设里的状态转移矩阵搬过来，用历史降雨序列预测未来 7 天降雨状态，输出"未来风险趋势"。

产出：一个 RiskService.java，输入时间/降雨，输出风险等级。

怎么算做完：给一场真实暴雨的降雨数据，输出的高风险区和新闻里实际积水点大致吻合。

这是你和其他候选人拉开差距的地方。大部分转行做 WebGIS 的人只会调地图 API，你能讲清"风险怎么算出来的"——这就是 GIS 专业出身的价值。

Vue3 + Cesium第 7–9 周约 30 小时

第 1 步 · 安装 Git

约 5 分钟

下载：官网 https://git-scm.com/download/win 在国内经常只有几十 KB/s，别等。直接用下面两个国内镜像（都是官方安装包的原样拷贝，文件签名一致）。

镜像链接实测速度
华为云（首选）https://mirrors.huaweicloud.com/git-for-windows/39.8 MB/s
版本最新，当前 2.56.1
淘宝 npmmirror
（备用）		https://registry.npmmirror.com/-/binary/git-for-windows/11.7 MB/s
当前 2.55.0.5

速度为本机 2026-11-19 实测。65MB 的安装包在华为云上约 2 秒下完，官网可能要半小时。

怎么点到具体文件：打开镜像目录后是一串版本文件夹（v2.56.1.windows.1/ 这种），挑版本号最大的那个点进去，再下 Git-2.56.1-64-bit.exe。

只下这两种文件名：
· ✅ Git-2.x.x-64-bit.exe ← 要这个，标准安装版
· ⚠️ PortableGit-2.x.x-64-bit.7z.exe ← 便携版，免安装。好处是完全不写 C 盘、不写注册表，解压到 D:\dev\Git 加个 PATH 就能用；代价是没有右键菜单、没有文件关联。想彻底不碰 C 盘可以选它
· ❌ MinGit- 开头的是给 CI/CD 用的精简包，不含完整功能，别下
· ❌ -arm64 是 ARM 芯片机器用的，你是 Intel i5-12600KF，选 64-bit
不放心文件安全性？下完右键安装包 → 属性 → 数字签名，签名者应为 Software Freedom Conservancy 或 Git for Windows。镜像站给的是官方原包，签名是对得上的。

安装：一路 Next，只在这两个地方留意——

  • 安装目录改成 D:\dev\Git（默认是 C 盘 Program Files，改到 D 盘）。
  • "Adjusting your PATH environment" 选 Git from the command line and also from 3rd-party software（默认选项）。
  • 其余全部默认。

验证：新开一个终端（Win+R 输入 cmd），执行：

git --version

看到 git version 2.x.x 即可。

顺手配置身份（提交记录会用到）：

git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
注意：装完必须重新打开终端，旧窗口读不到新的 PATH。

第 2 步 · 配置 JDK 21 （本机已装，跳过安装）

已安装约 2 分钟

本机实测：已安装 Microsoft JDK 21.0.7，路径 C:\Users\Administrator\AppData\Local\Programs\Microsoft\jdk-21.0.7.6-hotspot，java -version 正常。不需要重装，只需要补 JAVA_HOME（当前为空，不补的话 IDEA 构建和 Maven 会报错）。

怎么做：Win+R 输入 sysdm.cpl → 高级 → 环境变量 → 在系统变量里新建：

变量名：JAVA_HOME
变量值：C:\Users\Administrator\AppData\Local\Programs\Microsoft\jdk-21.0.7.6-hotspot

然后编辑系统变量 Path，新增一条：

%JAVA_HOME%\bin

验证（必须新开终端）：

echo %JAVA_HOME%
java -version

第一行显示出 JDK 路径（结尾不能带 \bin），第二行显示 openjdk version "21.0.7" 即完成。

两个必须注意的点：
① JAVA_HOME 只写到 JDK 根目录，不要写成 ...\bin——这是最高频的坑。
② 本机当前 Path 里已有 JDK 的 bin 直接路径，保留没问题，但也要加 %JAVA_HOME%\bin，否则 Maven 找不到。

（如果你后来想换成 Temurin 版：https://adoptium.net/temurin/releases/?version=21，选 Windows x64 JDK msi，安装时把 "Set JAVA_HOME variable" 设为本地安装。功能上微软版和 Temurin 版对本项目没有区别。）

第 3 步 · 安装 Node.js

本机需重装约 10 分钟

本机实测：虽然能查到 v22.22.2，但它位于 C:\Users\Administrator\.workbuddy\binaries\node\——是工具自带的副本，不在你的系统 PATH 里。你自己打开 CMD 敲 node 会失败。所以必须自己装一份。

当前 LTS 版本：v26.13.1（2026.11 核实；npm 11.20.0 随包附带）。

下载：https://nodejs.org/zh-cn/download，页面默认选中 LTS，点左下角 「Windows 安装程序(.msi)」。

① winget 在国内拉包同样慢，还会碰到源不可用；
② fnm 默认把 Node 装在 C:\Users\Administrator\AppData\Roaming\fnm，直接违背你"不装 C 盘"的要求，要改还得手动设 FNM_DIR；
③ 装完还要改 PowerShell profile、跑 fnm env 才能生效，多一层配置就多一个出错点。
你只有一个项目、只用一个版本，msi 一步到位，装到 D:\dev\nodejs 就行。

第 4 步 · 安装 PostgreSQL 18 + PostGIS 3.7

本机完全未装约 25 分钟这一步最关键

本机实测：无 psql 命令、无 PostgreSQL 服务、无任何安装目录，5432 端口空闲。要从头完整安装。这是全部 8 步里最耗时、最容易出错的一步，建议留出一整块时间，别在零碎时间做。
版本选择：选 18.7，不要选页面最上面的 19.0。
EDB 下载页现在列的是 19.0 / 18.7 / 17.12 / 16.16 / 15.20 / 14.25。看起来 19.0 最新，但它是 2026 年 9–10 月才发的首个大版本，而 PostGIS 3.7 的 Windows Bundle 2026 年 11 月 11 日才发布——你可能是第一批踩坑的人。
18.7 才是正确选择：PG 18 发布于 2025 年 9 月，已经修到第 7 个补丁版本，成熟；而且 PostGIS 官方明确写了「Bundle 3.7.0 installers for PostgreSQL 18–19」，Stack Builder 里一定选得到。
也不用退到 17：PostGIS 官网原文是「Installers for 15-17 are on the way」——3.7 的 15–17 版 Bundle 还没出，Stack Builder 里能不能选到旧版 Bundle 不确定，反而增加风险。
一句话：18 是「够新 + 够稳 + PostGIS 确定支持」三者唯一的交集。

下载：https://www.enterprisedb.com/downloads/postgres-postgresql-downloads
找到 18.7 那一行，点 Windows x86-64 列的下载图标（约 350MB）。

4.1 安装 PostgreSQL 本体：

  • 安装目录：改成 D:\dev\PostgreSQL\18（别放 C 盘默认路径，也别放中文路径）。
  • 数据目录：默认即可（会在安装目录下建 data）。
  • 组件：全选（PostgreSQL Server + pgAdmin 4 + Stack Builder + Command Line Tools）。
  • 超级用户密码：设一个你记得住的，比如 postgres。本地开发用，简单点没关系，但要记住。
  • 端口：5432，不要改。
  • 区域设置：默认。
  • 最后一步会出现 "Launch Stack Builder"，先勾上，点 Finish。

4.2 用 Stack Builder 装 PostGIS：

  • Stack Builder 启动后，选择刚装的 PostgreSQL 18 on port 5432，Next。
  • 展开 Spatial Extensions → 勾选名字里带 「for PostgreSQL 18」的那个 Bundle（写的是 PostGIS 3.7.0 Bundle for PostgreSQL 18；如果列表里显示 3.6.x for PG 18，选它也完全可用），Next。
  • 下载 → 一路 Next 安装，安装路径必须和 PostgreSQL 安装目录一致（D:\dev\PostgreSQL\18）。

4.3 建库并启用 PostGIS 扩展：

打开 pgAdmin 4（开始菜单里找），或直接用命令行：

cd D:\dev\PostgreSQL\18\bin
psql -U postgres

-- 进入 psql 后依次执行：
CREATE DATABASE floodgis;
\c floodgis
CREATE EXTENSION postgis;
SELECT postgis_version();

最后一行返回类似 3.7 USE_GEOS=1 USE_PROJ=1 USE_STATS=1 就成功了。\q 退出。

这一步的三个致命坑：
① PostGIS 版本必须匹配 PostgreSQL 主版本。PG 18 就必须选带「for PostgreSQL 18」的 Bundle，带 17 或 19 的都会失败。这一步看错一个数字，后面全废。
② CREATE EXTENSION 必须在目标库里执行。很多人忘了 \c floodgis，在 postgres 默认库里建，结果项目连的库没有扩展。
③ 忘了 postgres 密码 → 只能重装。装的时候就记在备忘录里。

第 5 步 · 安装 IntelliJ IDEA（统一版）

约 10 分钟

先说明：Community 版已经没有了，这不是你找错页面。
从 2025.3 版本起，JetBrains 把 Community Edition 和 Ultimate 合并成了一个统一版本，只提供一个安装包。原来 Community 的全部功能依然免费，而且免费范围内还多了几样东西。

下载：https://www.jetbrains.com/idea/download/ → 页面上只有一个下载按钮（Windows 版 .exe，当前 2026.3）。不用再找版本对比表，那个已经取消了。

免费范围到底包含什么（这是你最关心的）：

  • Java / Kotlin 全部核心开发功能 —— 和旧 Community 一致，永久免费，不需要激活码、不需要登录
  • 额外送的：Spring Boot 项目向导、Spring / Thymeleaf 基础语法高亮、数据库连接与表结构浏览、完整 SQL 支持
  • 要订阅才有的：完整 Spring 支持（Bean 跳转、依赖注入图）、前端框架深度支持、AI 助手、高级数据库工具

安装：安装目录改成 D:\dev\JetBrains（IDEA 本体加缓存能到 3–5GB，别放 C 盘），勾选创建桌面快捷方式。

第一次启动会问你试用：装完打开时会弹 Start 30-day Ultimate trial。有两个选择——

  • 点 Start trial：白拿 30 天完整功能（含完整 Spring 支持），不需要绑卡，到期自动降级
  • 点 Continue for free（或 Skip）：直接用免费功能，也完全够你做完这个项目

两个都不会锁死你。试用到期后不会打不开、也不用重装，只是高级功能变灰——这一点和很多商业软件不一样，可以放心点。

缓存位置：已处理完毕，无需再操作

本机已完成迁移，实际配置如下：
· 配置 D:\dev\cache\idea\config（13MB）
· 索引缓存 D:\dev\cache\idea\system（345MB，会随项目增长到 1–2GB）
· 日志 D:\dev\cache\idea\log
写入位置是 D:\dev\JetBrains\bin\idea.properties 末尾的三行（原文件已备份为 idea.properties.bak）。
注意：以后升级 IDEA 大版本时，安装器可能会覆盖 bin\idea.properties，届时检查一下这三行还在不在；丢了就重新加。

如果你想自己改（换机器时用）：打开 IDEA → Help → Edit Custom Properties → 写入上面三条路径，效果一样。

验证：能打开就算成功，第一次启动会让你选主题，随便选。

第 7 步 · 安装 Python + 空间数据处理库 （本机必做，当前是假 Python）

必须重装约 20 分钟

本机情况（已处理）：系统原来 PATH 里的 python 指向 C:\Users\Administrator\AppData\Local\Microsoft\WindowsApps\python.exe——微软商店的占位符，执行会跳转商店。
现已通过关闭「应用执行别名」清掉（设置 → 应用 → 高级应用设置 → 应用执行别名 → python.exe / python3.exe 两个开关）。换机器时这一步别忘。

已装完成，本机实际状态如下：

· 版本 Python 3.13.17，装在 D:\dev\Python313（C 盘零占用）
· Add python.exe to PATH 已生效，where python 只解析出一个路径，指向 D 盘
· WindowsApps 的两个别名桩（python.exe / python3.exe）已关闭
· pip 指向清华源，缓存目录 D:\dev\cache\pip
· 依赖已全部安装（31 个包，36 秒），site-packages 约 457MB
已装版本：geopandas 1.2.0 / rasterio 1.5.2 / shapely 2.2.0 / pyproj 3.8.0 / fiona 1.10.1 / pandas 3.1.1 / numpy 2.5.5 / psycopg2 2.9.13

换机器重装时这么做：

① 先清掉假 Python：设置 → 应用 → 高级应用设置 → 应用执行别名 → 关掉 python.exe 和 python3.exe 两个开关。

② 下载：https://www.python.org/downloads/，或国内镜像 https://mirrors.huaweicloud.com/python/<版本号>/（快得多）。

选版本有个坑：不要挑 3.13 分支里数字最大的那个。Python 的安全更新版（如 3.13.18）不提供 Windows 二进制安装包，下载会直接 404。
3.13 分支最后一个带完整安装包的是 3.13.17（29,941,280 字节）。下载后可用官方 python.org/ftp/python/3.13.17/ 对照文件大小。
安装界面第一屏点 Customize installation，不要点 Install Now——后者会把 Python 装进 C:\Users\...\AppData\Local\Programs\Python，路径改不了。
第一屏勾选 "Add python.exe to PATH"；到 Advanced Options 页把 Customize install location 改成 D:\dev\Python313，并确认 "Add Python to environment variables" 仍是勾上的。

验证（新开终端）：

python --version
where python

第一行应显示 Python 3.13.x；第二行应指向 D:\dev\Python313\python.exe，且只有一条结果——如果还出现 WindowsApps 那条，说明别名没关干净。

安装空间数据处理库：

python -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
python -m pip config set global.cache-dir D:/dev/cache/pip
cd D:\wb\urban-flood-gis\pipeline
python -m pip install -r requirements.txt

上面第三行用的是项目里现成的 requirements.txt，比手敲包名可靠。实测清华源下 31 个包 36 秒装完。

验证：

python -c "import geopandas, rasterio, shapely, psycopg2; print('ok')"

输出 ok 就成功。更彻底一点，跑一遍几何计算和坐标转换（这两项才能证明 GEOS / PROJ 真的可用）：

python -c "from shapely.geometry import Polygon; print(Polygon([(0,0),(0,1),(1,1),(1,0)]).buffer(0.5).area)"
python -c "from pyproj import Transformer; print(Transformer.from_crs('EPSG:4326','EPSG:3857',always_xy=True).transform(114.3,30.5))"

第一行应输出大于 1 的面积值；第二行应输出 (12723818.5..., 3567983.1...)，即武汉在 Web 墨卡托下的坐标。

如果 geopandas 或 rasterio 装不上（Windows 上偶发编译失败）：
① 先试升级构建工具：python -m pip install --upgrade pip setuptools wheel，再重装；
② 还不行就装 Miniforge（https://conda-forge.org/download/），然后用 conda install -c conda-forge geopandas rasterio，conda 的预编译包最稳。

四·五、C 盘保护：缓存与项目位置

光把软件装到 D 盘还不够——真正的 C 盘杀手是缓存和依赖仓库，它们默认全在 C 盘用户目录下，用着用着就吃进去十几 G。装完软件，把这几个也改到 D 盘。

1. npm 缓存（容易到 1–2GB）

npm config set cache "D:\dev\cache\npm"
npm config set prefix "D:\dev\cache\npm-global"
npm config get cache

2. pip 缓存

python -m pip config set global.cache-dir "D:\dev\cache\pip"

3. Maven 本地仓库（最容易失控，几个 G 很常见）

默认在 C:\Users\Administrator\.m2\repository。先建目录，再编辑或新建 C:\Users\Administrator\.m2\settings.xml：

<settings>
  <localRepository>D:/dev/cache/maven-repo</localRepository>
</settings>

IDEA 里也可以直接改：Settings → Build, Execution, Deployment → Build Tools → Maven → Local repository。

4. 项目位置

所有代码和数据放 D:\wb，不要放 C 盘的桌面或文档：

D:\wb\
├── urban-flood-gis\         ← 本项目
└── 2026-11-19-17-53-58\     ← 咨询产出工作区
为什么这么在意 C 盘：你现在 C 盘剩 71G，看着够用。但 node_modules（几百 MB）、Maven 仓库（几个 G）、DEM 与 GeoTIFF 数据（几百 MB）、IDEA 索引（1–2G）叠起来，半年就能吃掉 20G。提前规划好，比将来清理省事得多。

6.3 搭前端（Vue3 + Vite）

frontend 目录已经存在，Vite 脚手架需要空目录，所以先把占位文件删掉或用临时名生成后再合并。最简单的方式：

cd D:\wb\urban-flood-gis
npm create vue@latest frontend-tmp

交互式选项全部选 No（先不装路由、不装 Pinia），保持最简。生成后把 frontend-tmp 里的内容移到 frontend：

xcopy /E /I /Y frontend-tmp frontend
rmdir /S /Q frontend-tmp
cd frontend
npm install
npm install cesium vite-plugin-cesium
npm run dev

浏览器打开 http://localhost:5173，看到 Vue 默认页面即成功。

接入 Cesium（vite.config.js）：

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import cesium from 'vite-plugin-cesium'

export default defineConfig({
  plugins: [vue(), cesium()]
})

写第一个三维地球（src/App.vue）：

<template>
  <div id="cesiumContainer"></div>
</template>

<script setup>
import { onMounted } from 'vue'
import * as Cesium from 'cesium'

onMounted(() => {
  const viewer = new Cesium.Viewer('cesiumContainer', {
    baseLayerPicker: false,
    geocoder: false,
    animation: false,
    timeline: false
  })
  viewer.camera.flyTo({
    destination: Cesium.Cartesian3.fromDegrees(114.305, 30.593, 200000)
  })
})
</script>

<style>
#cesiumContainer { width: 100vw; height: 100vh; }
</style>

保存，浏览器里出现一个飞到武汉上空的三维地球——第一周就算完成了。

为什么第一周只做这个：你要先拿到"能跑起来"的确定感。一个能转的地球，比十个写了一半的模块更有价值——它会让你相信这件事可做。

七、避坑清单

坑表现解法
Git 官网下载龟速几十 KB/s，65MB 要下半小时换国内镜像：mirrors.huaweicloud.com/git-for-windows/（实测 40MB/s）或 registry.npmmirror.com/-/binary/git-for-windows/
GitHub push/clone 卡住git push 长时间无响应或 Failed to connect先 git config --global http.proxy 127.0.0.1:端口 走代理（有的话）；没有就先用 Gitee 私有仓过渡，别在这上面耗时间
JDK 版本不对Spring Boot 启动报 Unsupported class file major version确认 java -version 是 21，IDEA 里 Project Structure 的 SDK 也改成 21
PostGIS 装错版本CREATE EXTENSION postgis 报版本不兼容重跑 Stack Builder，选对应 PG 18 的 PostGIS 3.7 Bundle
扩展建错库项目连上但报 type "geometry" does not exist\c floodgis 后再 CREATE EXTENSION postgis
假 Pythonpython 跳转微软商店，pip 不存在PATH 指向 WindowsApps 占位符。卸载商店版 Python + 关闭应用执行别名，装官方版
工具链副本混淆命令能跑，但换个终端就失效开发工具内置的 Node/Git 不在系统 PATH。务必自己装一份，用 where node 验证路径
JAVA_HOME 为空IDEA 构建报找不到 JDK / Maven 报错新建 JAVA_HOME 指向 JDK 根目录，Path 加 %JAVA_HOME%\bin
端口被占用8080 或 5173 启动失败换端口（server.port=8081），或 netstat -ano | findstr :8080 找到进程 kill
Cesium 静态资源 404页面白屏，控制台报 Workers 加载失败必须用 vite-plugin-cesium，不能手动 copy 资源
npm 装依赖超时卡住或报 ETIMEDOUT已配淘宝镜像；还慢就 npm install --registry=https://registry.npmmirror.com
npm 权限报错EPERM 或 EACCES不要用管理员身份跑 npm，也不要装在 C:\Program Files 下
路径有中文各种诡异的编译/读取失败项目、JDK、PostgreSQL、Python 全部装英文路径
前端跨域浏览器报 CORS policy后端加 @CrossOrigin 或全局 WebMvcConfigurer 配置
GeoJSON 坐标不对图形飞到海里或偏移几百米统一用 EPSG:4326；ST_AsGeoJSON 默认就是 4326，别混用 3857
