============================================================
 城市内涝风险可视化平台 · 演示包说明
============================================================

这个文件是写给「演示当天的自己」看的，不是项目文档。
项目怎么设计、数据从哪来，请看仓库里的 README 和 docs/。


★★★★★ 先看这条，不然演示必翻车 ★★★★★
------------------------------------------------------------
必须用 http://127.0.0.1:8080/ 打开，不要用 http://localhost:8080/ 。

天地图 key 的域名白名单里只登记了 127.0.0.1，没有 localhost。
用 localhost 打开时浏览器发的 Referer 是 http://localhost:8080/，
天地图判定域名不符直接返回 403（code 301007「域名不符」），
后果是整张卫星底图一张瓦片都加载不出来，屏幕上只剩一个蓝色地球；
而时间轴、易涝点卡片、后端接口全都正常，极容易被误判成 Cesium 坏了。

127.0.0.1 和 localhost 在浏览器眼里是两个不同的域名，白名单不认后者。
启动脚本自动打开的就是 127.0.0.1，所以双击就能用；
只有你手敲地址、或者把窗口从历史记录里点回来的时候才会踩到。
以后换域名或上线，先去天地图控制台把新域名加进白名单，再改代码里的地址。


一、怎么用（三步）
------------------------------------------------------------
1. 双击 启动演示.bat
2. 等 8 秒左右，浏览器会自动打开 http://127.0.0.1:8080/
3. 演示结束后，关掉那个黑窗口，服务就停了

全过程不需要联网（除了 Cesium 的在线影像底图）、
不需要 Node、不需要 IDEA、不需要手动开数据库。


二、前置条件（换机器时先确认这三条）
------------------------------------------------------------
1. JDK 21
   命令行执行 java -version，输出里要有 21。
   版本低了会报 UnsupportedClassVersionError。

2. PostgreSQL 15 或更高，并且装了 PostGIS 扩展
   PostGIS 不装的话，导入备份时第一步就会卡在 CREATE EXTENSION postgis。

3. psql / createdb / pg_restore 在 PATH 上
   命令行执行 psql --version 能出版本号即可。
   不在 PATH 上也没关系，脚本会自动去
   D:\dev\PostgreSQL\*  和  C:\Program Files\PostgreSQL\*
   下面找一遍。


三、第一次运行会发生什么
------------------------------------------------------------
第一次跑会自己建库、导入数据，大约 10 秒，然后才启动服务。
之后再跑会跳过导入，直接启动（几秒）。
判断依据是数据库 floodgis 是否存在，存在就不动它，不会覆盖你已有的数据。

数据来源是 sql\floodgis_demo.dump（PostgreSQL 自定义格式备份）。
不要用仓库里 01_schema.sql 重建库——那只能建空表，
当前库里的 40 个易涝点是清洗对齐过的真实数据，只在备份里。


四、换电脑 / 换密码
------------------------------------------------------------
脚本默认用 postgres / 010704 连接 localhost:5432。
要改有两种办法：

1. 不改文件（推荐）：先设环境变量再双击
      set PGPASSWORD=你的密码
   或者在系统环境变量里加一条 PGPASSWORD。

2. 改默认值：用记事本打开 启动演示.bat，
   找到 set "PGPASSWORD=010704" 这一行，换成你的密码。
   注意这个 bat 是 GBK 编码（cmd 解析批处理的硬要求，文件头有详细说明），
   用记事本改没问题；用 VS Code 改的话，右下角编码要先选 GB2312/GBK 再保存，
   否则会存成 UTF-8，脚本一跑就满屏「不是内部或外部命令」。

端口不是 5432 的话，同样在那段里加一行 set "PGPORT=5433"。


五、常见故障四条
------------------------------------------------------------
1. 报「端口 8080 已被进程 PID xxxx 占用」
   上一次的窗口没关干净，或者 IDEA 里还跑着后端。
   执行 taskkill /PID xxxx /F 后重新双击脚本。
   想知道是谁占的：netstat -ano | findstr :8080

2. 报「没装 PostgreSQL，或者 psql 不在 PATH 上」
   装了但没配 PATH 最常见。把安装目录下的 bin 加进 PATH，
   然后重新打开一个命令行窗口（旧窗口不会自动刷新环境变量）。

3. 报「连不上 PostgreSQL 服务器」
   先看服务有没有启动（services.msc 里找 postgresql-x64-xx），
   再核对密码。密码错和数据库没启动，报错是同一句，
   脚本在这之前已经单独做过一次连接测试，所以这里基本都是密码问题。

4. 页面出来了，但只有蓝色地球、没有卫星底图（控制台一片 403）
   地址栏是不是 localhost？改成 127.0.0.1:8080 立刻恢复。
   原因见文件开头那条醒目提示：天地图白名单只认 127.0.0.1。
   判断方法：F12 看 Network，失败的瓦片请求返回 {"code":301007,"msg":"域名不符"}。

导入备份时如果刷出几条 ERROR（例如 role "xxx" 不存在），
属于 --no-owner 没覆盖到的历史对象，不影响数据。
判断标准很简单：服务起来后打开 /api/zones，能返回 40 个要素就说明数据是全的。


六、演示顺序建议（五分钟版）
------------------------------------------------------------
1. 先看全市视图——让观众先建立「武汉有多大、水在哪」的空间感，
   这一屏不要动鼠标，讲清楚底图是 DEM 重采样的淹没范围叠加。

2. 打开时间轴，拖到 2020-07-07。
   这是全片的高潮：把 2020 年 7 月那场暴雨的七天逐日推一遍，
   让观众自己看出淹水范围怎么长出来。拖动比讲参数有说服力。

3. 点一个高风险易涝点，把右侧卡片读出来
   （水深、风险等级、最近雨量站、影响范围）。
   这一步是为了证明「点得中、查得到、数据是联动的」，
   而不是一张贴图。

4. 如果还有时间，再打开 /status 说明一句：
   模型、数据、服务是一条链，前端只是最后一层皮。
